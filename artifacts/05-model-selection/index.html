Introduction

Model selection is a trade-off between predictive quality, resource constraints and the ability to explain decisions. Explainability requires more than a small model: stakeholders need reliable evidence about why predictions change and where a model fails.

Methodology

Representative published checkpoints were selected for contrasting deployment requirements. Parameter counts describe model size, not runtime memory. Accuracy is reported on the named task; speed is published timing rather than a local experiment. Vision accuracy uses Torchvision FP32 weights; timing uses separately reported INT8 models on Pixel 4. NLP accuracy is SST-2 development accuracy; speed is a complete STS-B development pass on CPU, batch size 1. TabPFN uses the original 2023 model with 32 permutations on 18 small numerical OpenML-CC18 datasets; timing is combined fit/predict overhead per dataset, not single-row latency. Do not rank domains by their raw scores or timings.

Analysis and recommendations

Language | customer feedback

DistilBERT reduces parameters by 40% and full-pass CPU time by about 39% relative to BERT. Start here for high-volume sentiment classification; consider BERT when the 1.4-point benchmark advantage matters. Validate token attributions through perturbation tests. Neither is a text-generation model.

Vision | edge inspection

MobileNetV3-Small is a reasonable first candidate for constrained devices. EfficientNet-B0 has about 10 percentage points higher published ImageNet accuracy but slower reported mobile latency. Compare defect recall and p95 latency on the actual device; inspect Grad-CAM against annotated regions.

Tabular | risk screening

TabPFN v1 is a candidate for small numerical classification problems with up to 1,000 training rows, 100 features and 10 classes. Use permutation importance and sensitivity checks; compare logistic regression or boosted trees for larger or regulated tasks. Benchmark on time-separated data and check calibration and subgroup errors.

Conclusion

There is no universal winner. Select a candidate within the task domain, set accuracy and latency thresholds, evaluate explanations for faithfulness, and validate on representative data before deployment. Monitor drift and reassess the choice when constraints change.
